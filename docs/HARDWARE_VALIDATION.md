- 仪器：`RIGOL TECHNOLOGIES,MHO98,MHO9A273700214,00.01.01`
- 通信：Windows 原生 USBTMC；VID `1AB1`，PID `0452`

## 实机发现与修复

1. 慢时基下 `NORMAL` 屏幕波形可能暂时只返回 2 点。现在必须取得请求的完整 1000 点，否则保持当前频点并延时重试。
2. 高频下“稳定周期 + 保存周期”可能只有数毫秒，不足以覆盖仪器配置稳定时间。现在每点驻留时间为周期计算值与 0.25 秒中的较大值。
3. 原时基恢复可能受命令顺序影响。现在先关闭输出、恢复 RUN/STOP，再设置原时基，并回读核验；不一致会重试并报告。
4. 一个该固件不支持的 AFG 负载查询曾使原生 USBTMC 读操作超时。通过 NI-VISA `clear()` 恢复接口；正式控制路径不使用该命令。
5. 编程手册和实机均确认 `:SOURce<n>:PHASe` 与 `:SOURce<n>:PHASe:SYNChronize` 可用。正式扫频现会在每个频点设定、回读相位并执行硬件相位对齐。

## 双 AFG 相位对齐与线缆/链路综合延迟

接线：AFG1→CH2（参考），AFG2→CH1（响应）；两路均为 1 Vpp、0°，CH1/CH2 均为 1×、DC 耦合。结果文件：

- `output/phase_validation/dual_afg_phase_raw_20260821_221154.csv`
- `output/phase_validation/dual_afg_phase_summary_20260821_221154.csv`
- `output/phase_validation/dual_afg_phase_result_20260821_221154.json`

测试从 100 kHz 升频至 10 MHz，再从 10 MHz 降回 100 kHz。每个方向 7 个频点，每点执行硬件相位对齐并重复冻结采集 3 次，即每个频率共 6 次结果：

| 频率 Hz | CH1−CH2 圆均值 ° | 6 次相位峰峰值 ° |
| ---: | ---: | ---: |
| 100000 | -0.106872 | 0.025352 |
| 200000 | -0.525994 | 0.069858 |
| 500000 | -1.505973 | 0.037138 |
| 1000000 | -3.075926 | 0.075742 |
| 2000000 | -5.835573 | 0.073398 |
| 5000000 | -14.772299 | 0.069487 |
| 10000000 | -29.135848 | 0.101627 |

相位随频率的线性拟合得到 CH1 相对 CH2 综合延迟 `+8.117798 ns`，直线拟合 RMS `0.117635°`，所有正弦拟合的最低 R² 为 `0.998916120`。升频和降频合并后的最差重复峰峰值仅 `0.101627°`，说明每次变频后执行硬件相位对齐具有良好重复性。

`+8.117798 ns` 不能直接归因于某一根射频线：它是 AFG2 相对 AFG1、两根 BNC 长度差和 CH1 相对 CH2 输入延迟的总和。要分离线缆本身，可交换两根线重复测试，或让同一个 AFG 经等长功分器接入 CH1/CH2 后运行 `calibrate_channel_loopback.py`。

## 加入相位同步后的单路正式扫频

结果文件：`output/hardware_validation/usb_loopback_validation_20260821_221210.csv`

AFG1→CH2 在 100、1000、10000 Hz 三点全部通过。每点 AFG 相位回读均为 `0°`、`phase_synchronized=True`；CH2 正弦拟合 R² 分别为 `0.999792409`、`0.999802086`、`0.999853600`。这验证了正式 `configure_sweep_point` 路径中的“设相位→回读→硬件对齐→动态时基→冻结采集”。
