# MHO98 正弦波上位机

运行 `python -m pip install -r requirements.txt`，然后执行 `python mho98_controller.py`。

连接方式：将示波器**后面板 USB Device**口用 USB 数据线连接电脑，或接入同一局域网并在软件中填写示波器的 **IP Address**。不要填写 DNS 或 Gateway；例如 `192.168.1.1` 通常是路由器/DNS 地址，并不是示波器地址。示波器的 IP Address 请在示波器网络设置页查看；电脑必须和它在同一网段（例如示波器为 `192.168.1.88` 时，电脑可设为 `192.168.1.100`，子网掩码均为 `255.255.255.0`）。

程序启动后会直接通过 Windows SetupAPI 查找“USB Test and Measurement Device (IVI)”，并通过 IVI `ausbtmc.sys` 原生 USBTMC 通道发送 `*IDN?`，不再依赖 PyVISA 的资源枚举。发现唯一设备时会自动连接；当前电脑上的 MHO98 资源应类似 `USB0::0x1AB1::0x0452::MHO9A273700214::INSTR`。PyVISA 仅作为兼容回退。

点击“扫描并连接 USB”或“连接 LAN”，软件会用 `*IDN?` 验证是否真的是 RIGOL 示波器；验证失败即保持未连接状态，绝不发送输出命令。LAN 会自动尝试 RIGOL 常用 SCPI 端口 5555 和 5025，并显示逐端口失败原因。

2.4 GHz USB 接收器一般仅供无线鼠标/键盘使用，并不是 MHO98 的远程控制接口，不能替代 USB Device 数据线或 LAN。

软件使用 MHO98 SCPI：`SOURce<n>:FUNCtion SINusoid`、`FREQuency`、`VOLTage:AMPLitude` 和 `SOURce<n>:OUTPut:STATe`。界面中两个滑条数值为线性映射；文本框可输入精确数值。

## 线性扫频

连接设备后，选择 GI/GII 通道并填写幅度，点击“开始扫频（0.1–500 Hz）”。程序分三段生成线性频率表：`[0.1, 10)` 100 点、`[10, 100)` 100 点、`[100, 500]` 100 点，共 300 个严格递增且不重复的频点（10 Hz 和 100 Hz 不会重复采集）。每点保持时间为 `5 / 频率`秒，即恰好 5 个周期。所有频点的理论保持时间约 4 分 36 秒，实际总时间还需加上 300 次 USB/LAN 波形传输和 CSV 写入时间。运行期间再次点击扫频或记录按钮，会停止扫频并关闭当前 AFG 输出。

UI 下方的预览窗口始终绘制 5 个周期，横轴会随频率自动改变，并标明 CSV 仅保存周期 2–4。预览代表发送给 AFG 的设定值，不是从示波器通道采集的实测波形。

## CH1 / CH2 电压采集

点击“开始记录”或“开始扫频”时，程序会先要求选择 CSV 保存位置，并立即在电脑上创建文件。每个频点的中间 3 周期数据提取完成后会立即追加到 CSV 并刷新到硬盘，无需等待整个扫频结束。
“导出 CSV 副本…”用于将已收到的内存数据另外复制一份；原始记录文件在采集过程中已经实时写入。Windows 原生 USBTMC 传输使用可取消的异步 I/O：写入默认 3 秒超时，波形读取默认 8 秒超时，不会再无限期占用仪器连接。

每个频点先运行完整 5 周期，再读取 CH1/CH2 屏幕原始波形。程序从每个通道最新的 5 周期窗口中只截取周期 2、3、4；周期 1 和 5 不写入 CSV。当前频点在数据传输完成前会继续保持，不会在读取过程中切换到下一频率。

数据记录只使用 `WAVeform:MODE NORMal` 依次读取 CH1 和 CH2 屏幕波形。它不会发送 `STOP`/`RUN`，也不会开关 CH1/CH2。扫频采用三个固定时基预设：`[0.1, 10)` Hz 使用 5 s/div，`[10, 100)` Hz 使用 50 ms/div，`[100, 500]` Hz 使用 5 ms/div；只在进入新频段时切换一次，段内100个点不改变时基。扫频结束或中途停止时恢复开始前的时基。

程序不再将数据强制插值成 1,000 Hz，而是保留示波器返回的原始电压点和 `XINCrement`。CSV 保存 `sweep_point`、`frequency_hz`、`period_s`、`cycle_number`、`point_time_s` 和 `sample_interval_s`。程序在真实时间上等待完整 5 周期；由于第 1 和第 5 周期都不保存，屏幕只需覆盖最后 4 周期即可完整提取第 2–4 周期，所以0.1 Hz下49.6秒的屏幕数据可以正常使用。每个频点提取完成后立即追加并刷新CSV，频段切换和波形读取期间不会提前切换到下一频率。

读取每个通道时，程序会确认该通道已在示波器上开启，回读并校验 `WAVeform:SOURce?`，再使用该通道的完整 `WAVeform:PREamble?` 和 ASCII 屏幕数据。MHO98 官方定义 ASCII 波形点本身就是实际电压，因此程序不会对 CH2 任意减去直流偏置。未连接的 1 MΩ 输入属于悬空输入，可能拾取噪声或串扰；若需要验证零电平，应将 CH2 输入接地或在示波器上临时选择 GND 耦合。

## 伯德图

伯德图以 CH1 为输入、CH2 为输出。程序在每个已知激励频率上，对两通道分别拟合 `a·sin(2πft)+b·cos(2πft)+c`，再计算幅值比 `CH2/CH1`、增益 `20·log10(CH2/CH1)` 和相位差 `φCH2-φCH1`。结果同时保存 CH1/CH2 拟合幅值、R²和有效点数，用于评估数据质量。

完整扫频结束后会自动生成伯德图；也可点击“用当前采集数据绘制”处理已完成的部分频点。“加载波形 CSV…”支持本程序生成的完整 CSV，也支持只有频率、CH1、CH2 三列的简化 CSV。简化 CSV 没有时间列时，程序会假设每个频率的数据等间隔覆盖 3 个周期。优先推荐提供 `point_time_s` 或 `sample_interval_s`，以获得可靠相位。

“保存伯德数据…”导出频率、两通道幅值、增益比、dB、相位、R²和点数；“保存伯德图…”可导出 PNG、SVG 或 PDF。
